## Що є у v8.3.x (коротко, від найважливішого)
- **Одна ризик-матриця + automode** — єдиний власник «скільки процесу / хто
  затверджує / скільки агентів»: **LOW** (зробив → один доказ), **NORMAL**
  (короткий план → виконує без затвердження → verifier), **HIGH** (план → моє
  затвердження → ревюер на кожен зачеплений ризик), **DESTRUCTIVE/гроші/прод/
  секрети** (завжди явний OK, повний pipeline). Сесійний перемикач
  **"automode on/off"** зсуває NORMAL→LOW; DESTRUCTIVE не зсувається ніколи.
- **SHERIFF** — зовнішній крос-вендорний ревюер (Codex CLI) для HIGH/DESTRUCTIVE
  діффів. Вимкнений за замовчуванням (перемикач у PROJECT, тримається між
  сесіями); разово — `/sheriff` або «шериф, глянь». Ізоляція ревюера — виконувана
  політика зі своїми тестами, не проза (скіл `cross-review`).
- **Context Guard** — захист від авто-компакції: одноразові підказки на порогах
  контексту, handoff перед компакцією, авто-resume після. Це **рантайм рівня
  машини** (`~/.claude/context-guard/`), ставиться один раз зі свого власного
  артефакту `context-guard-<version>.zip` — у проєкт НІКОЛИ не копіюється (копія
  в проєкті тихо вимикає спільний рантайм). Проєкт володіє одним файлом:
  `.claude/context-guard/config.json`. Опційно.
- **Гібридний стан виконання** (скіл `state-patch`): авторитетний структурований
  стан у `.agent/state/current.json` оновлюється детермінованим скриптом з
  патчів агента — транскрипт можна скинути будь-якої миті, handoff будується
  зі стану, Context Guard стає останньою сіткою, не першою.
- **Гейт закриває задачу, не слово агента.** `quality-gate.sh` перевіряє git-стан,
  секрети, lint/test/build, реальність run-звіту й `latest.json`. Будь-який RED /
  без доказів / необоротне / BLOCKED-гейт → стоп і клич людину.
- **Оновлення живого проєкту** — тільки через `UPGRADE.md`: новий реліз у
  `temp/template-new/`, команда «upgrade template», HIGH-row (план → мій OK →
  checkpoint-гілка → 3-way merge з моїм вето по файлах). CORE змінюється лише
  з Kernel Change Rationale + `core-baseline.sh`.
- **Реліз-гейт для мейнтейнера шаблону** (`scripts/release-check.sh`): збирає
  артефакт і перевіряє ВСЕРЕДИНІ розпаковки, а не в робочому дереві. GREEN —
  єдиний сигнал «ship». У звичайному проєкті скрипт чесно виходить з кодом 2.

## Як працює (коротко)
- `/start` → агент-практик проводить анкету й пропонує команду під проєкт (тільки
  core активні; решта — список рекомендацій; каталог ролей — `docs/ROLES.md`).
- `/research <тема>` → дослідити поточний стан ПЕРЕД планом (свіже > навченого).
- Перевіряючі — за ризиком (скіл `orchestration`), паралельно й незалежно;
  головний `verifier` зводить і повертає на допрацювання (зворотний цикл). До мене
  доходить лише суттєва незгода, що пережила цикл, — таблицею ескалації.
- Після будь-якої моєї правки — один рядок у `tasks/lessons.md`; те, що має
  триматися на 100%, стає хуком, а не текстом.

## Чесні застереження
- **Автоматичний ланцюг — так; автоматична довіра — ні.** Незалежність перевіряючих,
  зупинка на RED/без доказів, скінченний ланцюг і гейт як детермінований замок —
  саме це дає результат без самообману.
- **Межа «незалежності».** Внутрішні перевіряючі — одна базова модель: вони
  корельовані, спільні сліпі плями лишаються. Незалежність ЗНИЖУЄ, але не усуває
  rubber-stamping; саме тому є SHERIFF — інший вендор, інші ваги.
- **Хуки в конфігах агентів — best-effort** (у Codex вони вантажаться лише для
  trusted-проєктів і не на всіх версіях для Write/Edit). Гарантоване й
  агент-агностичне — git pre-commit (`install-git-hooks.sh`). Логіка скриптів
  доведена `test-hooks.sh`.
- **Вартість моделей.** Список моделей протухає, як зовнішній стан
  (`.claude/rules/model-selection.md`): спершу звір наживо, потім рішення у
  `decisions.md` з датою. Reviewers за замовчуванням — сильна модель (час >
  токени); де токени дорожчі — даунгрейдь не-high-risk ролі у їхніх файлах.

## Економія контексту
Спільне (definition-of-done, формат звіту, orchestration, artifact-versioning) —
раз у скілах, які читають усі агенти. У файлі агента — лише унікальне для ролі.
CLAUDE.md — kernel (ліміт 250 рядків, хук попередить). Гігієна контексту —
`.claude/rules/context-hygiene.md`: коли `/clear`, коли `/compact`, коли тримати
контекст теплим.

## Історія
Повний перелік змін по версіях — `CHANGELOG.md` (верхній запис = поточна версія,
записи без коду кажуть про це в перших рядках). Рішення по механізму
шаблону — `.agent/state/decisions.md`; походження sheriff-обгортки —
`docs/sheriff-provenance_*`. Польові проєкти в історії позначені як A/B/C —
жодне ім'я проєкту в шаблоні не фігурує (реліз-гейт це перевіряє по всьому дереву).
