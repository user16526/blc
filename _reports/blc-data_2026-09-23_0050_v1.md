# BLC data: Happy Hour re-baseline for a 2026-09-24 start (live DB, 2026-09-23)
Source: DB `bloody` via /mcpb (read-only). Internal accounts excluded with
`(flags & 64) = 0 AND (flags & 1) = 0` (unflagged QA list not applied — small).
Timestamps `timestamp without time zone`, assumed UTC (unverified, same as all prior pulls).
Purpose: refresh the 2026-09-08 inputs (`_reports/blc-data_2026-09-08_reach_v1.md`) with the
last 14 days of deposits and a 21-day reach window ending yesterday.

## Headline
**The 2026-09-08 design still holds: the last 14 days look like the 14 days before, 17-22 UTC is
still the peak, and the MDE barely moves (26.6 % rel vs 27.9 %).** Two new facts change the
plan text: (1) deposit promo #104 (deposit >= $25 -> case 809) ends 2026-10-07 23:59 UTC, so a
24.09 start has it on days 1-14 and without it on days 15-21; (2) first deposits are 33 % of in-window deposits, average $11.58,
so the 50 % bonus is worth ~$3 to a new client versus ~$11.50 to a returning one.

## SQL used
```sql
-- Q1
WITH d AS (SELECT d.client_id, d.amount, d.bonus_amount, d.paid_at, d.created
  FROM public.deposits d JOIN public.clients c ON c.id = d.client_id
  WHERE d._ab_cdc_deleted_at IS NULL AND (c.flags & 64) = 0 AND (c.flags & 1) = 0
    AND d.created >= '2026-08-26' AND d.created < '2026-09-23')
SELECT CASE WHEN created >= '2026-09-09' THEN 'B' ELSE 'A' END, count(*),
  count(*) FILTER (WHERE paid_at IS NOT NULL AND amount > 0), ...,
  count(DISTINCT client_id) FILTER (WHERE paid_at IS NOT NULL AND amount > 0),
  sum(amount) FILTER (WHERE paid_at IS NOT NULL)/100.0, sum(bonus_amount) ... FROM d GROUP BY 1;
-- Q2/Q3: same filter on paid_at 09.09-22.09, amount > 0; first = deposit_id in
--   analytics.first_deposit (created_at >= 2026-09-08); GROUP BY extract(hour from paid_at)
--   or (hour BETWEEN 17 AND 21, first/repeat); bonus applied = sum(bonus_amount)/sum(amount).
-- Q4
WITH l AS (SELECT r.client_id, max(CASE WHEN extract(hour from r.logged_at) BETWEEN 17 AND 21
    THEN 1 ELSE 0 END) AS in_win
  FROM public.client_login_records r JOIN public.clients c ON c.id = r.client_id
  WHERE r.logged_at >= '2026-09-02' AND r.logged_at < '2026-09-23'
    AND r._ab_cdc_deleted_at IS NULL AND (c.flags & 64) = 0 AND (c.flags & 1) = 0
  GROUP BY r.client_id),
dep AS (SELECT client_id, count(*) n FROM public.deposits WHERE paid_at >= '2026-09-02'
  AND paid_at < '2026-09-23' AND amount > 0 AND _ab_cdc_deleted_at IS NULL GROUP BY client_id)
SELECT count(*), sum(in_win), count(dep.client_id) FILTER (WHERE in_win=1), ...
FROM l LEFT JOIN dep USING (client_id);
-- Q5
SELECT id, deposit_amount/100.0, start_at, end_at, awards FROM public.deposit_promotions
WHERE _ab_cdc_deleted_at IS NULL AND end_at >= '2026-09-01';
```

## Caveats
- Reach = login in the window, an UPPER bound on exposure (same as 2026-09-08).
- Bots/bloggers and the unflagged internal list not excluded; effect is small at this volume.
- Free Ticket / Coins cost still not in the replica.
