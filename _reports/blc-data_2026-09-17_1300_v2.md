# BLC deposits drop — Sep 1–16 2026 vs Aug 1–16 2026 vs Sep 1–16 2025 (v2)
Source: live DB `bloody` via /mcpb, re-queried 2026-09-17. Supersedes v1 (same numbers, re-verified live) + adds country split and daily onset.
Excludes `clients.flags & 65`. Windows on `deposits.created` [1st, 17th), timestamp w/o tz (assumed UTC). Amounts cents/100, currencies not split (top countries are all USD).

## Verdict
Not seasonality, not demand. Payment success on PS 82 (≈90% of GMV) dropped from ~57% to ~48–51% starting around **2026-08-17** and has not recovered. Waiting won't fix it; the provider needs to be checked.

## Numbers
| window | attempts | people attempting | paid rate | depositors | GMV | FTD | PS82 rate |
|---|---|---|---|---|---|---|---|
| 2025-08 1–16 | 5897 | 2118 | 53.7% | 1280 | 59,363 | 678 | 60.8% |
| 2025-09 1–16 | 6379 | 2190 | 49.8% | 1305 | 64,560 | 721 | 56.6% |
| 2026-08 1–16 | 5815 | 2249 | 47.2% | 1137 | 55,668 | 637 | 57.2% |
| 2026-09 1–16 | 6265 | **2676** | **37.1%** | 1086 | **46,863** | 607 | **48.2%** |

- Seasonality: 2025 Aug→Sep GMV +9%; 2026 Aug→Sep −16%.
- Demand: people trying to deposit +19% vs Aug, but people who succeeded −5%.

The drop is uneven. It is concentrated in TR and CZ, and to a lesser degree in US, GB and DE; UA and PL are barely affected. This points to a provider or issuer routing/decline change for specific card regions, not a site-wide break (inference, unverified).

Daily PS 82 onset: Aug 10–16 ran at 56–64%; Aug 17–18 fell to 46%, followed by 50–55% with noise.

## Caveats
- Status meaning (paid = `paid_at` set) is inferred, not taken from app code. Payment system ids are unnamed in the replica.
- The DB can't tell issuer declines from abandoned checkouts; that needs the provider dashboard or dev logs.
- Country is the deposit's `country` column (source unverified: IP vs card BIN).
- PS 94 attempts rose +55% at ~5% success (v1). These are likely retries after PS 82 fails (unverified).

## SQL
```sql
-- windows summary
WITH w(label, s, e) AS (VALUES ('2025-08','2025-08-01','2025-08-17'),('2025-09','2025-09-01','2025-09-17'),('2026-08','2026-08-01','2026-08-17'),('2026-09','2026-09-01','2026-09-17')),
d AS (SELECT w.label, dp.id, dp.client_id, dp.amount, dp.paid_at, dp.payment_system_id ps FROM w
  JOIN public.deposits dp ON dp.created >= w.s::timestamp AND dp.created < w.e::timestamp
  JOIN public.clients c ON c.id = dp.client_id
  WHERE dp._ab_cdc_deleted_at IS NULL AND (c.flags & 65) = 0)
SELECT d.label, count(*) attempts, count(*) FILTER (WHERE d.paid_at IS NOT NULL) paid,
  count(DISTINCT d.client_id) attempters,
  count(DISTINCT d.client_id) FILTER (WHERE d.paid_at IS NOT NULL) depositors,
  round(sum(d.amount) FILTER (WHERE d.paid_at IS NOT NULL)/100.0) gmv, count(DISTINCT fd.client_id) ftd,
  count(*) FILTER (WHERE d.ps=82) ps82_att,
  round(100.0*count(*) FILTER (WHERE d.ps=82 AND d.paid_at IS NOT NULL)/nullif(count(*) FILTER (WHERE d.ps=82),0),1) ps82_rate
FROM d LEFT JOIN analytics.first_deposit fd ON fd.deposit_id = d.id GROUP BY 1 ORDER BY 1;

-- PS 82 by country, before/after Aug 17
WITH d AS (SELECT CASE WHEN dp.created < '2026-08-17' THEN 'A' ELSE 'B' END per,
  coalesce(dp.country,'?') country, dp.currency, dp.paid_at
FROM public.deposits dp JOIN public.clients c ON c.id = dp.client_id
WHERE dp._ab_cdc_deleted_at IS NULL AND (c.flags & 65) = 0 AND dp.payment_system_id = 82
  AND dp.created >= '2026-07-17' AND dp.created < '2026-09-17'),
top AS (SELECT country FROM d GROUP BY 1 ORDER BY count(*) DESC LIMIT 8)
SELECT d.country, d.currency,
  count(*) FILTER (WHERE per='A') att_a,
  round(100.0*count(*) FILTER (WHERE per='A' AND paid_at IS NOT NULL)/nullif(count(*) FILTER (WHERE per='A'),0),1) rate_a,
  count(*) FILTER (WHERE per='B') att_b,
  round(100.0*count(*) FILTER (WHERE per='B' AND paid_at IS NOT NULL)/nullif(count(*) FILTER (WHERE per='B'),0),1) rate_b
FROM d JOIN top USING (country) GROUP BY 1,2 HAVING count(*) > 150 ORDER BY att_b DESC;

-- PS 82 daily onset
SELECT dp.created::date d, count(*) att,
  round(100.0*count(*) FILTER (WHERE dp.paid_at IS NOT NULL)/count(*),1) rate
FROM public.deposits dp JOIN public.clients c ON c.id = dp.client_id
WHERE dp._ab_cdc_deleted_at IS NULL AND (c.flags & 65) = 0 AND dp.payment_system_id = 82
  AND dp.created >= '2026-08-10' AND dp.created < '2026-08-25'
GROUP BY 1 ORDER BY 1;
```

## Funnel SQL (added for `deposit-funnel_2026-09-17_v1.html`)

-- logged-in, sign-ups, status mix per window
WITH w(label, s, e) AS (VALUES ('2025-08','2025-08-01','2025-08-17'),('2025-09','2025-09-01','2025-09-17'),('2026-08','2026-08-01','2026-08-17'),('2026-09','2026-09-01','2026-09-17')),
lg AS (SELECT w.label, count(DISTINCT l.client_id) active FROM w JOIN public.client_login_records l ON l.logged_at >= w.s::timestamp AND l.logged_at < w.e::timestamp GROUP BY 1),
reg AS (SELECT w.label, count(*) regs FROM w JOIN public.clients c ON c.created >= w.s::timestamp AND c.created < w.e::timestamp WHERE (c.flags & 65)=0 AND c.deleted_at IS NULL GROUP BY 1),
st AS (SELECT w.label, dp.status, count(*) n FROM w JOIN public.deposits dp ON dp.created >= w.s::timestamp AND dp.created < w.e::timestamp WHERE dp._ab_cdc_deleted_at IS NULL GROUP BY 1,2)
SELECT w.label, lg.active, reg.regs, (SELECT string_agg(st.status||':'||st.n, ' ' ORDER BY st.status) FROM st WHERE st.label=w.label) statuses
FROM w LEFT JOIN lg USING(label) LEFT JOIN reg USING(label) ORDER BY 1;

-- people funnel, new vs returning, intended amount of never-payers
WITH w(...same 4 windows...),
d AS (SELECT w.label, dp.client_id, dp.amount, dp.paid_at, (c.created >= w.s::timestamp) is_new FROM w
  JOIN public.deposits dp ON dp.created >= w.s::timestamp AND dp.created < w.e::timestamp
  JOIN public.clients c ON c.id = dp.client_id
  WHERE dp._ab_cdc_deleted_at IS NULL AND (c.flags & 65) = 0),
pc AS (SELECT label, client_id, bool_or(is_new) is_new, bool_or(paid_at IS NOT NULL) paid,

SELECT label, count(*) attempters, count(*) FILTER (WHERE paid) payers,

  count(*) FILTER (WHERE NOT is_new) old_attempters, count(*) FILTER (WHERE NOT is_new AND paid) old_payers,
  round(sum(gmv) FILTER (WHERE is_new)/100.0) gmv_new, round(sum(gmv) FILTER (WHERE NOT is_new)/100.0) gmv_old
FROM pc GROUP BY 1 ORDER BY 1;
