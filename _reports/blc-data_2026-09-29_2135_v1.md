# Turkey payments — DB + GA4, May 2025 → Sep 2026 (weekly, monthly, Sep vs Sep)
Source: live replica `bloody` via postgres MCP + GA4 Data API (property from `.env`), queried 2026-09-29. Days UTC (assumed).
Turkey = `deposits.country = 'TR'`; GA4 country = `Türkiye` (no Singapore filter needed). Money USD (cents/100). Sep 2026 = days 1–28.
Page: `_reports/turkey-payments_2026-09-29_v1.html`.

## TL;DR
1. Zen (ps 82) success in TR, % of attempts paid: Sep 2025 63.3% · Jun–Aug 2026 63.7% · Sep 2026 46.0%. Lowest month in 17; the other 16 months ranged 56.6–67.1%.
2. Demand is UP vs last year: Sep 1–28 clients who tried to pay 212 → 358 (+68.9%), attempts 1066 → 1147. Paying clients 103 → 137; client success 48.6% → 38.3%.
3. GMV Sep 1–28 $21,151 → $20,450 (−3.3%): more payers but fewer paid deposits (606 → 444); avg paid deposit $34.9 → $46.1. Vs summer 2026: GMV/day $1,250 → $731 (vs Aug alone −32.1%).
4. Break date: Zen client success Aug 25–31 71%, Sep 1–5 75%, from Sep 6 49%. Starts 09-06, ~2 days before the event launch (09-08) → not caused by the event.
5. The drop is in every group (new and repeat payers, every amount band except $100+, which is 14 clients) → payment side, not player mix.
6. Other countries' Zen success is also falling (59% May → 49% Sep; biggest step Aug → Sep) — possibly a Zen-wide component; TR fell sharper, in one week.
7. Estimate, not fact: at the Sep 2025 client success rate, ≈37 more payers ≈ $5,513 GMV in Sep 1–28.
8. Not visible in the replica: decline reasons (`payment_system_response` empty for all Sep TR Zen attempts; status 3 = decline or abandon). All TR attempts are USD.

## Caveats
- `deposits.country` meaning (IP vs card vs profile) not verified. GA4 country is session IP, so GA4 and DB are close, not equal.
- Deposits include the unflagged internal accounts (as in earlier reports).
- Status 1 (pending) rows existed until Jun 2026 and are ~0 since Jul; success = paid / all attempts, so it is not affected. Status-3 counts are.
- Monthly GA4 add_payment_info / purchase are event counts, not users.
- GA4 `purchase` for TR = 0 from 2026-05-20 to 2026-06-23 (tracking gap; DB paid deposits normal); weeks 05-18 and 06-22 partial → May/Jun 2026 GA4 purchase understated.
- Lost-payers estimate assumes the Sep 2025 client success rate would apply to Sep 2026 attempters.

## SQL
```sql
-- monthly (weekly = same with date_trunc('week', …) and range 2026-05-04 → 2026-09-28)
with a as (
  select to_char(date_trunc('month', created), 'YYYY-MM') as m,
    count(*) as att, count(distinct client_id) as att_c,
    count(*) filter (where status = 2) as ok, count(distinct client_id) filter (where status = 2) as ok_c,
    count(*) filter (where status = 3) as s3,
    count(*) filter (where payment_system_id = 82) as z_att, count(*) filter (where payment_system_id = 82 and status = 2) as z_ok,
    count(distinct client_id) filter (where payment_system_id = 82) as z_c, count(distinct client_id) filter (where payment_system_id = 82 and status = 2) as z_ok_c,
    round(avg(amount) / 100.0, 1) as avg_try
  from public.deposits
  where country = 'TR' and created >= '2025-05-01' and created < '2026-09-29' and _ab_cdc_deleted_at is null
  group by 1),
p as (
  select to_char(date_trunc('month', d.paid_at), 'YYYY-MM') as m, count(*) as n, count(distinct d.client_id) as payers,
    round(sum(d.amount) / 100.0) as gmv, count(f.deposit_id) as ftd
  from public.deposits d left join analytics.first_deposit f on f.deposit_id = d.id
  where d.country = 'TR' and d.paid_at >= '2025-05-01' and d.paid_at < '2026-09-29' and d._ab_cdc_deleted_at is null
  group by 1)
select a.*, p.n, p.payers, p.gmv, p.ftd from a left join p on p.m = a.m order by a.m limit 30;

-- Sep 1-28 YoY (cohort by created)
select extract(year from created) as y, count(*), count(distinct client_id),
  count(*) filter (where status = 2), count(distinct client_id) filter (where status = 2), count(*) filter (where status = 3),
  count(*) filter (where payment_system_id = 82), count(*) filter (where payment_system_id = 82 and status = 2),
  count(distinct client_id) filter (where payment_system_id = 82), count(distinct client_id) filter (where payment_system_id = 82 and status = 2),
  round(sum(amount) filter (where status = 2) / 100.0), round(avg(amount) / 100.0, 1), round(avg(amount) filter (where status = 2) / 100.0, 1)
from public.deposits where country = 'TR' and _ab_cdc_deleted_at is null
  and ((created >= '2025-09-01' and created < '2025-09-29') or (created >= '2026-09-01' and created < '2026-09-29'))
group by 1 order by 1 limit 5;

-- Zen status mix by month, TR vs other
select to_char(date_trunc('month', created), 'YYYY-MM'), case when country = 'TR' then 'TR' else 'other' end, status, count(*)
from public.deposits where created >= '2026-05-01' and created < '2026-09-29' and _ab_cdc_deleted_at is null and payment_system_id = 82
group by 1, 2, 3 order by 1, 2, 3 limit 50;

-- currency + response presence (aggregate only; response text never selected)
select case when created < '2026-09-01' then 'jun-aug' else 'sep' end, coalesce(currency, '?'), count(*), count(*) filter (where status = 2),
  count(*) filter (where payment_system_response is not null and payment_system_response <> '')
from public.deposits where country = 'TR' and payment_system_id = 82 and created >= '2026-06-01' and created < '2026-09-29'
  and _ab_cdc_deleted_at is null group by 1, 2 limit 20;

-- new vs repeat, amount bands
with z as (select d.created, d.amount, d.status, d.client_id,
    case when exists (select 1 from analytics.first_deposit f where f.client_id = d.client_id and f.created_at < d.created) then 'repeat' else 'new' end as who
  from public.deposits d where d.country = 'TR' and d.payment_system_id = 82 and d.created >= '2026-06-01' and d.created < '2026-09-29'
    and d._ab_cdc_deleted_at is null)
select case when created < '2026-09-01' then 'a_jun-aug' else 'b_sep' end as per, 'who:' || who as k, count(*), count(*) filter (where status = 2),
  count(distinct client_id), count(distinct client_id) filter (where status = 2) from z group by 1, 2
union all
select case when created < '2026-09-01' then 'a_jun-aug' else 'b_sep' end, 'amt:' || case when amount < 1000 then '1 <$10' when amount < 2000 then '2 $10-19'
  when amount < 5000 then '3 $20-49' when amount < 10000 then '4 $50-99' else '5 $100+' end,
  count(*), count(*) filter (where status = 2), count(distinct client_id), count(distinct client_id) filter (where status = 2) from z group by 1, 2
order by 2, 1 limit 30;

-- daily TR Zen 08-25 → 09-28
select to_char(created, 'MM-DD'), count(*), count(*) filter (where status = 2), count(distinct client_id), count(distinct client_id) filter (where status = 2)
from public.deposits where country = 'TR' and payment_system_id = 82 and created >= '2026-08-25' and created < '2026-09-29'
  and _ab_cdc_deleted_at is null group by 1 order by 1 limit 40;
```
GA4 Data API runReport: dimensionFilter country = "Türkiye"; dimensions date (+ eventName in add_payment_info, purchase; split into
2025-05-01→2025-12-31 and 2026-01-01→2026-09-28 to stay under the row limit); metrics sessions, totalUsers, newUsers, keyEvents, eventCount.
Aggregated offline to Monday weeks and calendar months. `sign_up` / `begin_checkout` are not tracked for TR (not in the Sep event list).
