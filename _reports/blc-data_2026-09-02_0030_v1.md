# BLC data: standing deposit bonus — 1st deposit vs 2+ (live DB, 2026-09-02)
Source: DB `bloody` via /mcpb (read-only Postgres MCP), table `public.deposits`, paid deposits
(`paid_at IS NOT NULL`), last 90 days as of 2026-09-02. Money unit: cents (USD). Bonus = `bonus_amount`.
Purpose: closes Happy Hour blocker #1 (standing first-deposit bonus % was unknown).

## Headline
**First deposit gets a standing 20 % bonus (25 % when the deposit is ≥ ~$19.76). Deposits 2+ get 6–10 %,
mostly 6–7 %.** The bonus is applied on 99.9 % of first deposits and 100 % of second deposits; on 3+ deposits
only 54 % carry a bonus.

| ordinal | deposits (90 d) | % with bonus | avg bonus % when given | bonus as % of total amount | avg deposit |
|---|---|---|---|---|---|
| 1st | 3 147 | 99.9 | 20.8 | 22.05 | $10.84 |
| 2nd | 1 097 | 100.0 | 7.0 | 7.15 | $13.47 |
| 3+ | 10 779 | 54.3 | 6.7 | 6.96 | $31.17 |

|---|---|---|---|

| 2+ | 6 | 3 944 | $19.00 – $48.88 |

First deposit: clean amount tiering (20 % below ~$19, 25 % from ~$19.76). Deposits 2+: 6 % and 8 % look
amount-tiered ($19–49 → 6 %, $99–190 → 8 %), while 7 % and 10 % overlap every amount band, so a second
factor (gateway, promo, VIP level, campaign) drives them. Referral presence and deposit `type` do NOT change
the %. Not resolved here; ask dev if it matters.

## History
`bonus_amount` is 0 for every deposit before May 2026 (85 % of 1st deposits carry it in 2026-05, 99.7 %+
from 2026-06). Either the column was introduced in May 2026 or the standing bonus started then. Treat as:
the 20 % / 25 % first-deposit bonus has been live since ~May 2026.

## Implication for Happy Hour (winner-take-max, not additive)
- A Deposit-Bonus prize of ≤ 20 % is a **no-op for every first deposit**, and ≤ 25 % is a no-op for first
  deposits ≥ $20. Only HH slots ABOVE 25 % change anything for new clients.
- For returning clients (2+), the standing bonus is 6–10 %, so any HH slot ≥ 10 % strictly beats it.
  HH slots of 10 / 20 / 30 % are meaningful for returning clients, mostly a no-op for new ones.
- This supports blocker #2's follow-on: give new clients a different prize type (Free Ticket / Coins) and
  reserve Deposit Bonus for returning clients, or set HH slots at 30 %+ if new clients must be included.
- `prize_cost` must log the APPLIED delta (HH % − standing %) × amount, not the nominal HH %, or the primary
  metric counts money the client would have received anyway (blocker #3).

## SQL used
```sql
WITH d AS (
  SELECT client_id, amount, coalesce(bonus_amount,0) AS bonus, paid_at,
         row_number() OVER (PARTITION BY client_id ORDER BY paid_at, id) AS n
  FROM public.deposits
  WHERE paid_at IS NOT NULL AND _ab_cdc_deleted_at IS NULL AND amount > 0
)
SELECT CASE WHEN n=1 THEN '1st' WHEN n=2 THEN '2nd' ELSE '3+' END AS dep_ordinal,
       count(*) AS deposits,
       sum(CASE WHEN bonus>0 THEN 1 ELSE 0 END) AS with_bonus,
       round(100.0*sum(CASE WHEN bonus>0 THEN 1 ELSE 0 END)/count(*),1) AS pct_with_bonus,
       round(100.0*sum(bonus)/sum(amount),2) AS bonus_pct_of_total_amount,
       round(avg(CASE WHEN bonus>0 THEN 100.0*bonus/amount END),1) AS avg_bonus_pct_when_given,
       round(avg(amount)/100.0,2) AS avg_amount_units
FROM d
WHERE paid_at >= now() - interval '90 days'
GROUP BY 1 ORDER BY 1 LIMIT 10;
-- tiers: same CTE, GROUP BY dep_ordinal, round(100.0*bonus/amount), with min/max(amount), HAVING count(*)>=20
-- history: same CTE, GROUP BY to_char(date_trunc('month', paid_at),'YYYY-MM'), dep_ordinal, last 180 days
```

## Caveats
- `paid_at` is `timestamp without time zone`; assumed UTC (not verified against a known event).
- Ordinal = rank among the client's PAID deposits over all time; the 90-day filter is applied after ranking.
- Bots/bloggers NOT excluded here (the 2026-08-26 hour-of-day analysis excluded them; this one did not).
- Whether the 25 % / 10 % tiers come from amount, promo or VIP level is inferred from ranges, not config.
- `deposit_promotions` is a different mechanism ("deposit ≥ $X → free case"; one active: ≥ $25 → case 776,
  ends 2026-09-09) and has no bonus-% field.
