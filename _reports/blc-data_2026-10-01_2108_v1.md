## Method
- **Opening one case** = a drop row in `public.client_items` with `reason = 'main case win: case id [N]'`. Excluded: battles, upgrades, free/daily, events and bots.
- **One go (one open)** = consecutive drops of the **same case by the same client** less than 1 s apart.
  - Calibrated on the last 24 h: drops inside one open land 0.2–0.7 s apart; the next open comes ≥1 s later (mostly 3–60 s, the spin animation), with almost nothing at 1–3 s.
  - The sizes come out cleanly at 1–5 and 10, which matches the site's open-count options.
- **Paid user** = at least one paid deposit at any time (`deposits.paid_at IS NOT NULL`).
- Excluded:
  - `clients.flags & 1`, `flags & 64` and `deleted_at`
  - the QA cluster 4041/6042/6046/6049/6052/6715/9162/17678 (`_reports/blc-data_2026-09-09_0041_v1.md`)

## SQL used
Batch-size distribution. The other queries reuse the `o`/`s`/`b` CTEs and change only the last aggregation.
```sql
with o as (
  select ci.client_id, ci.reason, ci.created,
    case when ci.created - lag(ci.created) over (partition by ci.client_id, ci.reason order by ci.created) < interval '1 second' then 0 else 1 end as starts
  from public.client_items ci
  where ci.reason >= 'main case win' and ci.reason < 'main case wio'
    and ci.created >= now() - interval '90 days'
    and ci._ab_cdc_deleted_at is null
),
s as (select client_id, reason, sum(starts) over (partition by client_id, reason order by created rows unbounded preceding) as batch_no from o),
b as (select client_id, reason, batch_no, count(*) as n from s group by 1,2,3),
bc as (select client_id, least(n, 11) as sz, count(*) as batches from b group by 1,2)
select bc.sz as batch_size, sum(bc.batches) as batches, count(distinct bc.client_id) as users
from bc
join public.clients c on c.id = bc.client_id
where c._ab_cdc_deleted_at is null and (c.flags & 1) = 0 and (c.flags & 64) = 0 and c.deleted_at is null
  and c.id not in (4041,6042,6046,6049,6052,6715,9162,17678)
  and exists (select 1 from public.deposits d where d.client_id = c.id and d.paid_at is not null and d._ab_cdc_deleted_at is null)
group by 1 order by 1;
```
Average check: aggregate `b` → one row per client with `bool_or(n = k)` flags for each size. Join `clients`, plus a `cross join lateral` sum and count of `deposits` where `paid_at >= now() - interval '90 days'` (all USD, cents / 100). Expand to cohorts with a `values` list, then avg check = Σ amount / Σ deposits.

Per-case table: aggregate `b` → (client, reason), then `array_agg` per client, join `clients` at client level, `unnest`, then group by case. Joining clients to (client, reason) rows directly times out.

## Caveats
- About 275 unflagged internal accounts aren't excluded; only the 8-account QA cluster is (the full list was never saved).
- The window runs from now() back 90 days, so July is partial (from 07-03) and October is a few hours.
- Opens that cross a midnight month boundary count in the month their first drop landed.
- Not all paid opens are bought with deposited money: they can use balance from sell-backs, bonuses or codes. "Paid user" describes the user, not the open.
- An open that fails partway would show as a smaller size. The 0.2–0.7 s spacing makes merging two separate opens unlikely (9 opens of 11+ in 90 days).
