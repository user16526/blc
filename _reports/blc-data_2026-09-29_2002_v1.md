Visual: `_reports/start-season-event_2026-09-29_v1.html`.

## Verdict
**Engagement: yes. Money: no.** In the first 20 days, active event participants were +20% vs the 20 days before launch, and
3+/7+-day retention matched the previous event's launch (−6% / −8%). FTD +10%. **GMV −18%** vs the 20 days
before and **−25%** vs the previous launch. Payer count held (~1,270); what dropped was deposit size. ARPPU excl. the
top 10 went 40 → 35.5 → 31.4 $, a decline that started before this event. Registrations flat (−2%).

The event-join spike on Sep 8–9 (1,320 / 2,830 vs ~550/day) is existing users entering the new event. Everyone who deposits
is automatically an event earner (payers = earners' payers), so deposits can't be attributed to the event.

## Caveats
- Event still running (8 days left); comparison is equal 20-day windows.
- `stats.event_transactions` type/source enums are unmapped; "active" = any type=1 tx (XP, inferred).
- Deposits/FTD do not exclude the unflagged internal accounts (see 2026-09-09 report); registrations use the real-user predicate.
- Window A is summer (seasonality), B is the old event's tail, and neither is a clean control. Treat these numbers as correlation, not causation.

## SQL
Daily:
```sql
with days as (select g::timestamp as d from generate_series('2026-08-01'::timestamp,'2026-09-28'::timestamp,'1 day'::interval) g),
reg as (select date_trunc('day',created) d, count(*) n from public.clients
  where created >= '2026-08-01' and created < '2026-09-29' and (flags&1)=0 and (flags&64)=0
    and deleted_at is null and _ab_cdc_deleted_at is null group by 1),
ftd as (select date_trunc('day',created_at) d, count(*) n from analytics.first_deposit
  where created_at >= '2026-08-01' and created_at < '2026-09-29' group by 1),
dep as (select date_trunc('day',paid_at) d, count(distinct client_id) payers, sum(amount)/100.0 gmv from public.deposits
  where paid_at >= '2026-08-01' and paid_at < '2026-09-29' and _ab_cdc_deleted_at is null group by 1),
ev as (select date_trunc('day',created_at) d, count(*) n from stats.event_clients
  where created_at >= '2026-08-01' and created_at < '2026-09-29' and _ab_cdc_deleted_at is null group by 1)
select to_char(days.d,'YYYY-MM-DD') day, coalesce(reg.n,0) reg, coalesce(ftd.n,0) ftd, coalesce(dep.payers,0) payers,
  round(coalesce(dep.gmv,0)) gmv_usd, coalesce(ev.n,0) event_joins
from days left join reg on reg.d=days.d left join ftd on ftd.d=days.d left join dep on dep.d=days.d left join ev on ev.d=days.d
order by 1 limit 60;
```
Windows (engagement + money):
```sql
with w as (
  select 'A_prev_launch' k,'ddcce517-e46a-47b9-adf7-8e2c9e09338f'::uuid ev,'2026-07-22 13:00'::timestamp s,'2026-08-11 13:00'::timestamp e
  union all select 'B_prev_tail','ddcce517-e46a-47b9-adf7-8e2c9e09338f'::uuid,'2026-08-18 20:00','2026-09-07 20:00'
  union all select 'C_new_launch','ae9a967d-a97c-4996-8e8c-60eef48c57e7'::uuid,'2026-09-08 20:00','2026-09-28 20:00'),
tx as (select w.k, t.client_id, count(distinct date_trunc('day',t.created_at)) days
  from w join stats.event_transactions t on t.event_id=w.ev and t.created_at>=w.s and t.created_at<w.e
  where t._ab_cdc_deleted_at is null and t.type=1 group by 1,2)
select k, count(*) earners, count(*) filter (where days>=3) d3, count(*) filter (where days>=7) d7 from tx group by 1;
-- + same windows over public.deposits (sum(amount)/100, count(distinct client_id)), public.clients (real predicate),
--   analytics.first_deposit; top-10 split via row_number() over (partition by k order by client_gmv desc).
```
