## A. Рекомендація (UA, для власника)

**Робимо два прогони замість одного.** Спочатку тест ПРИЗУ в одному вікні 18–21 UTC
(контроль / бонус на депозит 30-40-50 % / кейс), 3 тижні. Потім тест ЧАСУ (контроль / 02 UTC /
18 UTC) з призом-переможцем, ще 3 тижні, після тижня паузи і з новою рандомізацією.
Основна метрика — частка залогінених клієнтів групи, що зробили депозит, і депозитів на
клієнта за повний день. Виручка (з обрізанням китів на $500) — лише guardrail.

Чому так:
- Стандартний бонус на 1-й депозит 20/25 %, бекенд бере максимум → бонус ≤ 25 % для нових
  клієнтів порожній. Питання «який приз» стало важливішим за «яке вікно».
- «Зранку бонус, ввечері кейс» без другого прогону не розділяє час і приз; з обміном —
  відповідь лише на 6-му тижні і без оцінки взаємодії.
- За 3 тижні тест бачить приріст частки депозиторів від ~19 %, а приріст виручки — лише від
  ~45 % навіть з обрізанням. Рішення по виручці за 3 тижні неможливе.
- Вечірнє вікно несе 19 % депозитів, ранкове 5 %; нових клієнтів 24 % в обох.

Що потрібно від Євгена: роутинг група → планер для двох планерів о 18 UTC (зміна мапінгу,
не новий шар), три події для вартості призів, збереження групи в БД, перерандомізація для
прогону 2. Якщо роутинг неможливий — власник обирає: чекати відповіді 6 тижнів (кросовер)
або лишити лише питання вікна (план менеджера).

Дати: прод не раніше 2026-09-10 (кінець акції «депозит ≥ $25 → кейс 776»). Стоп вручну на
22-й день. Увесь план ≈ 7 тижнів.

## B. ТЗ (RU) — Happy Hour A/B, v2

### 1. Цель и метрики
- Цель: понять, поднимает ли Happy Hour депозиты и какой приз / какое окно работает.
- **Основная метрика:** доля клиентов группы (залогиненных, получивших `happy_hour_gate_shown`),
  сделавших ≥ 1 оплаченный депозит за прогон, и число депозитов на клиента — за ПОЛНЫЙ день,
  не только в окне (ловим перенос депозитов во времени).
- **Guardrail:** чистый прирост выручки = Δ депозитов − стоимость призов, депозиты клиента
  обрезаны на $500 за прогон (28 китов держат 37 % оборота).
- Разрез new / returning — пост-хок, не отдельная ветка.
- Ограничение честности: за 3 недели тест видит прирост доли депозиторов от ~19 %
  (база 5.0 %). Меньший эффект будет невидим — фиксируем это ДО старта.

### 2. Структура: два прогона
**Прогон 1 — приз (21 день).** Одно окно **18:00–21:00 UTC** (максимальный охват).
Группы по хэшу `client_id`, фиксированы на прогон, 33.3 % каждая:
- G0 — контроль, ничего не видит;
- G1 — Deposit Bonus;
- G2 — кейс (PromoCode, если тип есть в планере; иначе FreeTicket).
Реализация: два планера с `cron 0 18 * * *`, duration 180, is_cyclic = true, разные пулы призов;
фронт ведёт группу на свой `happy_hour_id`.

**Пауза 7 дней** — Happy Hour выключен.

**Прогон 2 — время (21 день).** Приз-победитель прогона 1 в обоих планерах.
Группы **заново** рандомизированы (новый experiment id / соль хэша):
G0 контроль / G1 окно 02:00–05:00 UTC / G2 окно 18:00–21:00 UTC — как уже реализовано.
Ежедневно, одинаково все 21 день, без вариаций по дням недели.

### 3. Участие (одинаково для всех веток обоих прогонов)
- Условие: Make Deposit ≥ **$5** (медиана первого депозита $5.99; $10 отсекает большинство новых).
- Анти-фарм: Not Participated in 24 hours.
- Без участия без условий.

### 4. Призы
- G1 пул: Deposit Bonus **30 % / 40 % / 50 %** — три слота, равновероятно (Weight бэкендом
  игнорируется). Ниже 30 % приз невидим для новых (стандартный бонус 20/25 %), ниже 10 % —
  почти для всех. Срока действия у бонуса в бэкенде нет — давление времени создаёт само окно.
- G2 пул: один кейс на весь прогон, стоимость **$5–10** — паритет с ожидаемой стоимостью
  бонуса (≈ 0.4 × средний депозит $20 ≈ $8). Конкретный кейс — выбор владельца.
- Пулы одинаковы в обоих окнах прогона 2.
- Только то, что работает сегодня. Всё, что требует доработки, — тикет, не слот.

### 5. Логирование (обязательно, иначе метрика не считается)
Уже есть: `happy_hour_gate_shown`, `happy_hour_shown`, `happy_hour_spun`. Требования и добавления:
- `happy_hour_gate_shown` — один раз на клиента за прогон, для ВСЕХ групп включая контроль;
  это индексное событие. В нём: `client_id`, `group`, `experiment_id`, `is_new_client`
  (= нет оплаченного депозита до момента этого события), `ts`.
- `happy_hour_prize_won` — результат спина: `client_id`, `group`, `happy_hour_id`, `prize_type`,
  `prize_amount` (номинал), `case_id`, `ts`.
- `happy_hour_prize_applied` — для Deposit Bonus, в момент депозита: `deposit_id`,
  `deposit_amount`, `nominal_pct`, `standing_pct`, `applied_pct`,
  `prize_cost` = (applied − standing) % × amount, в центах.
- `happy_hour_prize_redeemed` — для FreeTicket / PromoCode, в момент использования:
  `prize_type`, `case_id`, `value` (цена билета / кейса, центы). Не использован = стоимость 0.
- `group` и `experiment_id` сохраняются в БД по `client_id` и джойнятся с `deposits`.

### 6. Даты и стоп
- Прод: не раньше **2026-09-10** (до 09-09 действует акция «депозит ≥ $25 → кейс 776»; в окне
  18–21 UTC под неё попадает 32 % депозитов — кейс в призе задвоил бы награду).
- Стоп: вручную `is_active = false` на обоих планерах утром 22-го дня. Поле end-date — тикет,
  не блокер.
- Тикеты на потом: реальный выбор по Weight; вернуть проверку «один спин в день»; end-date.
