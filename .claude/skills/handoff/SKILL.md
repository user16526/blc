# Handoff — передача стану задачі між сесіями

НЕ плутати з git-скілом `checkpoint` (той робить restore point у git перед
ризикованою зміною). Handoff — це стан ЗАДАЧІ для виживання контексту.

## Режим 1: Створення / оновлення

1. Не читай нових файлів (виняток: `git rev-parse` / `git status` для метаданих).
2. Якщо current.md існує і це НОВА задача — перенеси старий у
   `.claude/handoffs/archive/YYYY-MM-DD-HHMM.md`. Якщо та сама задача —
   просто онови розділи 2, 5, 6, 7 і метадані.
3. Ціль: < 150 рядків.
4. Durable-висновки handoff НЕ замінює: важливі рішення → `.agent/state/decisions.md`,
   уроки → `tasks/lessons.md` (роутинг — skill `memory-router`). Handoff —
   ефемерний робочий стан, він локальний і не комітиться.
5. Роботу після цього НЕ зупиняй — продовжуй задачу.

### Шаблон

    # Handoff: <назва задачі>
    Дата: <YYYY-MM-DD HH:MM>
    Branch: <git branch> · HEAD: <short sha> · Dirty: yes/no
    Task status: ACTIVE

    ## 1. Ціль
    ## 2. Зроблено
    ## 3. Змінені файли
    ## 4. Архітектурні рішення
    ## 5. Що НЕ спрацювало (не повторювати!)
    ## 6. Тести / стан збірки
    ## 7. Наступна конкретна дія (рівно ОДНА, імперативно)
    ## 8. Відкриті питання / ризики

Правила: розділ 5 не пропускати, якщо були невдалі спроби; без великих
шматків коду; не переказувати вміст файлів, які можна прочитати.

## Режим 2: Відновлення (/continue-work)

1. Читай current.md ТІЛЬКИ якщо `Task status: ACTIVE` (DONE — ігноруй і скажи це).
2. Якщо git HEAD відрізняється від зазначеного — попередь користувача.
3. Live-факти в handoff — вказівники, не докази: перед дією перевір живий стан
   (`.claude/rules/verify-external-state.md`).
4. Підтверди ціль і наступну дію одним рядком, виконуй розділ 7.
5. Коли задача завершена — постав `Task status: DONE`, запропонуй перенести в
   архів і виконай /session-log (outcome-запис телеметрії).

## Зв'язок зі станом (v8.3.16, skill `state-patch`)
Handoff — це ЗНІМОК для інʼєкції після clear/compact, а не єдиний дім фактів.
Якщо `.agent/state/current.json` ведеться (а він має вестися безперервно),
розділи 1/2/4/5/6/7 будуються З нього: goal, verified, decisions,
failed_rejected, latest_evidence, next. Унікальних фактів у handoff бути не
повинно — все durable уже в state/ledger до моменту створення знімка.
