Repeated procedures should become skills — but noticing the repetition is a duty,
not a hope. And creation is PROPOSED, never silent: a self-authored skill is
self-modifying configuration, so the human approves it first (this is always a HIGH-row action in the RISK MATRIX).

## The trigger (rule of three)
Doing the same multi-step procedure for the ~3rd time → STOP and propose extracting
it into `.claude/skills/<name>/`. Hints that you are repeating: a recurring line in
`tasks/lessons.md`, similar step sequences across `_reports/runs/`, déjà vu while
writing the plan.

## What a proposal looks like (one short message)
Proposed name + a one-line trigger description + the steps it would freeze.
If approved → write it with the `skill-authoring` skill (criteria, shape,
frontmatter, testing live there).

## Not everything is a skill
One-off → leave it in context. Recurring FACT → memory (`memory-router`).
Must hold 100% of the time → hook, not skill. Repeated twice, unlikely to recur →
a one-liner in `lessons.md` is enough.

## Prune what never fires
A skill that has not triggered in a long while is a deletion candidate — propose
removing it the same way. Every skill costs tokens on load; a stale one is
negative value.
